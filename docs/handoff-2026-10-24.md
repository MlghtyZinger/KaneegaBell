## Standing decisions and working rules

- **Publishing is pre-approved** (memory `publish-auto-accept`). Run `powershell -ExecutionPolicy Bypass -File "C:\Emulator files\tools\release\release.ps1" -Version X.Y.Z -Publish -Yes` in the Terminal panel (`run_in_terminal`) so the owner types the updater key password themselves; never ask for it in chat. Commit first (the script needs a clean tree), bump the README patch notes heading to the new version, and check that tag `vX.Y.Z` and its GitHub release do not already exist: the script reuses an existing build for an existing tag (this caused a stale 0.3.14).
- One milestone per release; the release order is locked (see `CLAUDE.new1.md`); milestone v was added last. Remind the owner before reordering. The perf gate is only for major updates or startup/grid/idle changes; the Achievements window is a new screen, so run `tools/perf/perf.ps1` before the release that includes it and say so in the notes.
- Never touch `C:\Games\KaneegaBell`. The dev exe build (`npm run tauri build -- --no-bundle`) is fine even while the installed copy runs; check the dev exe path before assuming a lock. PATH in the shell needs `C:\Program Files\nodejs` and `C:\Users\watch\.cargo\bin`.
- Every command given to the owner includes `C:\Emulator files` (cd or absolute path). Patch notes are player-facing, concise, big features only.
- Use the app's theme variables (`--bg-raised`, `--accent`, `--gold`, `--border`...) so every style (Ember default, Midnight, Daylight...) works. No animated blur or large filters; animate only transform and opacity.
- Browser-preview check: `preview_start ui-mock` (Vite on 1420 with the mock IPC). Skip the intro with Esc, then `Right` + `f` opens details for a game with achievements.
